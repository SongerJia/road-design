## 1. 策略模式？

**锚点**：GoF / JDK 源码（`Comparator`、`ThreadPoolExecutor`）

- [ ] **及格**：**算法族封装成策略对象**，运行时自由切换；结构 = 策略接口 + 多个实现 + 上下文持有策略引用；解决**大量 if-else 分支**
- [ ] **良好**：及格 + 能解释为什么用——符合**开闭原则**（新增策略不改上下文）、消除条件分支；**JDK 经典实例**：`Comparator`（排序策略）、**线程池拒绝策略**（`RejectedExecutionHandler` 四种策略）；**策略 vs 状态**（策略由外部指定，状态由内部自动转换）
- [ ] **精通**：良好 + 能应对追问——**策略 + 简单工厂**配合（工厂按需创建策略）、**Lambda 简化策略**（策略是函数式接口时直接传 lambda）、策略 vs **模板方法**（组合 vs 继承）、策略模式如何**消除 if-else 的实战**写法

## 2. 观察者模式？

**锚点**：GoF / JDK `Observable`（已废弃）/ Spring 事件

- [ ] **及格**：**一对多依赖**——主题状态变化时自动通知所有观察者；结构 = Subject + Observer 列表；解决**发布者与订阅者耦合**
- [ ] **良好**：及格 + 能解释——为什么用（**解耦**，发布者不感知订阅者）、**推模型 vs 拉模型**、JDK 的 `Observable`/`Observer` 已废弃的原因（只支持一个 Observable、无序列化约束）、**消息队列是观察者的分布式版**
- [ ] **精通**：良好 + 能应对追问——观察者 vs **发布-订阅**（有无中间层/消息总线）、**Spring 事件机制**（`ApplicationEvent` + `ApplicationListener` + `@EventListener`）、**监听器内存泄漏**（注册后未移除，尤其在静态集合中）、与**响应式编程**（RxJava/流）的关系

## 3. 模板方法模式？

**锚点**：GoF / Spring `JdbcTemplate`、`RestTemplate`

- [ ] **及格**：**父类定义算法骨架，子类实现可变步骤**；可选**钩子方法**（子类决定是否执行某步骤）；解决**复用骨架 + 控制扩展点**
- [ ] **良好**：及格 + 能解释为什么用——复用公共流程、**把不变的定死、把变化的开放**；经典实例——**Spring 的 `JdbcTemplate`**（连接管理定死，SQL 与结果集处理留给子类/回调）、`RestTemplate`；**好莱坞原则**（"别调用我们，我们会调用你"）
- [ ] **精通**：良好 + 能应对追问——**钩子方法的作用**（让子类影响算法走向）、模板方法 vs **策略模式**（继承复用 vs 组合委托）、模板方法里的 **final 方法**为什么不能被重写、与**工厂方法**的配合（可变步骤里用工厂）

## 4. 责任链模式？

**锚点**：GoF / Servlet Filter、Spring MVC 拦截器

- [ ] **及格**：**请求沿处理器链传递**，每个处理器决定处理或转发下一个；结构 = 处理器接口 + 链表串联；解决**发送者与接收者解耦**
- [ ] **良好**：及格 + 能解释为什么用——**动态组合处理链**（可增删处理器）、避免 `if-else` 长链；**经典实例**——**Servlet Filter**（过滤器链）、**Spring MVC 拦截器**（`HandlerInterceptor`）、日志过滤器/鉴权过滤器
- [ ] **精通**：良好 + 能应对追问——责任链 vs **装饰器**（责任链是"处理或不处理、传递"，装饰器是"增强并继续"）、**中断 vs 继续传递**的设计（如权限校验失败是否终止）、**Netty 的 ChannelPipeline**、**MyBatis 拦截器**（`InterceptorChain`）、链的顺序如何保证

## 5. 状态模式？

**锚点**：GoF / 状态机

- [ ] **及格**：**状态封装成对象**，对象的行为随内部状态改变而改变；结构 = 状态接口 + 多个状态实现 + 上下文持当前状态；解决**大量状态判断 if-else**
- [ ] **良好**：及格 + 能解释——为什么用（状态转换逻辑集中、消除状态判断分支、新增状态不影响其他状态）；**状态 vs 策略**的核心区别（**策略**：外部指定算法，状态不变；**状态**：内部自动转换，行为随状态变）；典型例子——订单状态、电梯状态
- [ ] **精通**：良好 + 能应对追问——**状态转换由谁触发**（上下文 vs 状态自身，两种设计的取舍）、状态模式 vs **工作流引擎**（状态机 vs 流程编排）、**Spring Statemachine** 框架、什么时候不该用状态模式（状态少且稳定时）
