## 1. 适配器模式？

**锚点**：GoF / 《Head First 设计模式》

- [ ] **及格**：将一个类的接口**转换成客户端期望的接口**；两种实现——**类适配器**（继承）与**对象适配器**（组合，更常用）
- [ ] **良好**：及格 + 能解释为什么用——**兼容不匹配的接口**（旧系统/第三方库接入）；对象适配器 vs 类适配器的取舍（组合优于继承）；**适配器 vs 外观**的区别（适配器是转换接口，外观是给子系统开新门面）
- [ ] **精通**：良好 + 能应对追问——**Spring MVC 的 `HandlerAdapter`**（适配不同 Controller 类型）、日志框架适配器（slf4j 适配 log4j/logback）、**什么时候不该用适配器**（与其适配不如重构，适配器会掩盖设计问题）

## 2. 代理模式？

**锚点**：GoF / Spring AOP 源码

- [ ] **及格**：代理 = 替真实对象**控制访问**（拦截 + 增强）；**静态代理**（手写代理类）vs **动态代理**（运行时生成）
- [ ] **良好**：及格 + 能说出两种动态代理——**JDK 动态代理**（基于接口，`Proxy` + `InvocationHandler`）vs **CGLIB**（基于继承，字节码生成）；**Spring AOP 就是代理模式的应用**；代理的用途（访问控制、日志、事务、延迟加载）
- [ ] **精通**：良好 + 能应对追问——**代理 vs 装饰器**（代理是控制访问、不改变功能；装饰器是增强功能、透明包装）、**同类内部调用代理失效**的原因、**远程代理/虚拟代理/保护代理**三种变体、代理对象的创建时机与开销

## 3. 装饰器模式？

**锚点**：GoF / JDK IO 流

- [ ] **及格**：**动态地给对象添加职责**；包装器（Wrapper）结构——装饰器与真实对象实现同一接口，层层包裹
- [ ] **良好**：及格 + 能解释为什么用——**替代继承**来扩展功能（避免类爆炸），符合**开闭原则**；**经典例子：JDK IO 流**（`BufferedInputStream` 装饰 `FileInputStream`）；**装饰器 vs 代理**（增强功能 vs 控制访问）、**vs 适配器**（同接口增强 vs 异接口转换）
- [ ] **精通**：良好 + 能应对追问——**透明 vs 半透明装饰器**（是否暴露被包装对象的特有方法）、装饰链**顺序的影响**（如 `BufferedOutputStream` + `ObjectOutputStream` 的先后）、**MyBatis 的 Cache 装饰**（LruCache/FifoCache 装饰 PerpetualCache）、与继承的**取舍原则**

## 4. 桥接模式？

**锚点**：GoF / JDBC 设计

- [ ] **及格**：**抽象与实现分离**，让**两个维度独立变化**；结构 = 抽象类持有实现接口引用
- [ ] **良好**：及格 + 能解释为什么用——多维度变化时**继承会爆炸**（如形状 × 颜色，2×2 需要 4 个类，桥接只需 2+2）；**经典例子：JDBC**（`DriverManager` 抽象 + 各家 Driver 实现）；桥接 vs **适配器**（事前设计 vs 事后兼容）
- [ ] **精通**：良好 + 能应对追问——桥接与**组合**的关系（桥接本质是组合）、怎么**识别"两个变化维度"**（画出变化轴，交叉点就是桥接的候选）、桥接与**抽象工厂**的配合（工厂负责选实现）、桥接 vs **策略**（结构层面 vs 行为层面）

## 5. 外观模式 & 组合模式？

**锚点**：GoF

- [ ] **及格**：**外观** = 为子系统提供统一门面，简化客户端调用；**组合** = 树形结构中**统一对待单个对象与组合对象**（叶子与容器同一接口）
- [ ] **良好**：及格 + 能解释——外观为什么用（**屏蔽子系统复杂性**、减少客户端与内部耦合）；组合的结构（`Component` 抽象 + `Leaf`/`Composite`）、**经典例子**（文件系统、组织架构、GUI 组件树）；透明 vs 安全组合（接口是否暴露子节点方法）
- [ ] **精通**：良好 + 能应对追问——**外观 vs 中介者**（外观是单向门面，中介者是双向协调）、组合与**递归**的关系（遍历树）、**什么时候不该用外观**（不要给本来就简单的系统加门面）、组合模式在 **MyBatis / 菜单系统**中的实例
