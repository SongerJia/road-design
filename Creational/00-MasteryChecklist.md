## 1. 单例模式：写法演进与线程安全？

**锚点**：《设计模式》GoF / Effective Java 第 3 条

- [ ] **及格**：定义——一个类全局只有一个实例；两种基础写法——**饿汉式**（类加载即创建）与**懒汉式**（首次使用时创建）
- [ ] **良好**：及格 + 能说出线程安全演进——懒汉加 `synchronized`（性能差）→ **双重检查锁（DCL）+ volatile** → **静态内部类**（懒加载 + 线程安全）→ **枚举单例**
- [ ] **精通**：良好 + 能应对追问——**DCL 为什么必须加 volatile**（`new` 三步可能重排，半初始化对象被别的线程读到）、**枚举单例为什么最安全**（JVM 保证枚举单例，且天然防反射/反序列化破坏）、单例与 **Spring 单例 Bean** 的关系（容器级单例 vs JVM 级单例）、单例的**缺点**（违背开闭、隐藏依赖、难测试）

## 2. 工厂模式：工厂方法 vs 抽象工厂？

**锚点**：GoF / 《Head First 设计模式》

- [ ] **及格**：三种形态——**简单工厂**（一个工厂方法，switch 创建）、**工厂方法**（父类定义接口，子类决定创建哪个对象）、**抽象工厂**（创建一族相关对象）
- [ ] **良好**：及格 + 能解释为什么需要工厂——**解耦创建与使用**、符合**开闭原则**（新增产品不修改已有代码）；**工厂方法 vs 抽象工厂**的核心区别：工厂方法靠**继承**、每次创建一个**产品**；抽象工厂靠**组合**、创建一**族产品**（产品族一致性）
- [ ] **精通**：良好 + 能应对追问——**Spring 的 BeanFactory 属于什么工厂**（更像"简单工厂/容器工厂"）、工厂模式与**建造者模式**的区别（工厂一步创建 vs 建造者分步组装）、什么时候不该用工厂（对象创建简单时，过度设计）

## 3. 建造者模式：解决什么问题？

**锚点**：GoF / Effective Java 第 2 条

- [ ] **及格**：**分步构建**复杂对象；`Builder` 与 `Director` 的协作；典型场景——**参数很多的对象**
- [ ] **良好**：及格 + 能解释为什么用——参数过多时**构造器可读性差**（参数位置易错）、**分步可校验**、能构建**不可变对象**；**Effective Java 的静态内部 Builder** 写法（链式调用）；与**工厂模式**的区别（工厂是"一步产出"，建造者是"分步组装"）
- [ ] **精通**：良好 + 能应对追问——建造者 vs **原型模式**（组装 vs 复制）、`Lombok @Builder` 的原理（生成静态 Builder 类）、建造者适合的**反例**（对象简单时用 Builder 是过度设计）、建造者与**不可变对象**的关系

## 4. 原型模式：浅拷贝 vs 深拷贝？

**锚点**：GoF / Java `Object.clone()` 文档

- [ ] **及格**：原型 = 通过**复制已有对象**创建新对象，而非 new；实现靠 `Cloneable` + `clone()`；**浅拷贝**（复制引用）vs **深拷贝**（复制内部对象）
- [ ] **良好**：及格 + 能解释为什么用原型——**创建成本高**（初始化耗时/依赖多）时复制更高效；`Object.clone()` 是 **protected**，需要实现 `Cloneable` 并重写；浅拷贝的**坑**（内部可变对象被共享）
- [ ] **精通**：良好 + 能应对追问——**为什么 Java 不推荐用 clone()**（绕构造器、破坏 final 字段、`Cloneable` 只是标记无方法）、深拷贝的**实现方式**（重写 clone 逐层拷贝 / 序列化反序列化 / 手动复制构造器）、原型 vs **工厂**的场景选择、**Spring 的原型 scope** 与原型模式的关系
